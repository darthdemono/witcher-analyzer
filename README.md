# witcher-analyzer

**Read a Witcher 1 save and get back a plain report of the run: Geralt's level and gold, what he carries, every quest and where it stands, and what he has learned to brew. Browser or command line.**

A Witcher save is a 25 MB bag of quest files, item lists and area dumps, and the game never adds them up for you. I wanted the total: how far along I am, what is in my pack, which quests are open and what each one wants next. This prints it. Give it a folder of saves and it prints the history instead, in the order the saves were made.

## Use it

```
python3 witcher_to_md.py                              # the newest save it can find on this machine
python3 witcher_to_md.py "000041 - Swamp Forest-038.TheWitcherSave" -o run.md     # Markdown
python3 witcher_to_md.py "000041 - Swamp Forest-038.TheWitcherSave" -o run.json   # JSON, against schema.json
python3 witcher_to_md.py saves/ -o history.md         # a whole folder: forks, journey charts, first-appearance tables
python3 -m http.server 8777 --bind 127.0.0.1         # then open http://127.0.0.1:8777/ for the web app
```

The Python side is the standard library. The web app wants a browser with `DecompressionStream`, which is anything current. Mermaid, for the charts in the combined view, is vendored.

## How far it reads

Every file inside a save gets decoded: Geralt himself, all 137 quest files, the quest database, the map state, and every module with its areas. The last line of each report counts the bytes no reader claimed. On all 75 of my saves that count is zero, and `tests/test_saves.py` fails if it stops being zero.

The report prints one other number next to it: a few thousand bytes of leftover table space inside the quest files that nothing points at. That is dead space the game's writer leaves behind, not data the reader missed, so it gets its own figure instead of hiding in the first one.

## What it can't tell you

- **Play time.** The save carries no clock. The combined history orders saves by slot number and says so.
- **The game's own ability names.** Item, quest and area names are stored in the save in English. Abilities are stored as internal ids, so `StyleSteelStrong1` is shown as "Style Steel Strong 1".
- **Anything about the other Witcher games.** I have no saves from them, so I haven't tried.

## The game tables

`db_tw1/` holds item names, item kinds and sign names. They come from the installed game: `tools/gamefiles.py build <Data folder> db_tw1` reads the KEY and BIF archives, the 2DA tables and the string file, and opens the game's files read-only. The tables ship with the repo, so the analyzer needs no install to run.

## Layout

- `witcher/` is the Python reader: `container.py` (header, file index, modules), `gff.py` (the BioWare GFF format every resource uses), `tw1.py` (the summary), `render.py`, `combine.py`.
- `app/` is the same logic in JavaScript, plus `view.js` (the DOM cards), `mdview.js` (Markdown to DOM, never innerHTML), `main.js` and `worker.js`.
- `schema.json` is the JSON contract, generated by `tools/gen_schema.py`.
- `notes/format.md` is the file format as implemented.

## Two readers, one answer

The browser port is checked against the Python reader byte for byte. `tools/parity.mjs` runs both over the same saves and fails on any difference in the summary, the Markdown or the combined document. A port drifts silently otherwise.
